# メール送信の機能

## 安全策（必須）

- **ボタン1つで即送信は絶対に作らない**
- 必ず付ける：
  1. 送信前の確認画面（プレビュー → 最終確認の2段階）
  2. 送信先の選択
  3. 文面の編集
  4. 送信後の取り消し（遅延送信など）
- cron 用のエンドポイントと管理画面の UI は分ける
- 教訓：2026-08-14 に確認画面なしで215名に誤送信し、全員に謝罪メールを送った

## 外部設定を先に全部確かめる

実装の前に外部依存リストを出す。メール送信では次を全部確認する：

- 送信ドメインの DKIM / SPF（DMARC も）
- 開封・クリック計測（Open/Click Tracking）の CNAME
- Webhook（配信・バウンス・苦情）
- 環境変数

## 端から端までの確認

- 実データで1通テスト送信 → DB に `opened_at` などが記録されるところまで確かめる
- bounced / complained のアドレスを自動で除外する処理が無いなら、無いと明示する
- テスト送信も実際の送信なので、送り先は中森さんの確認を取ってから
