# 秘密の値の受け渡し

中森さんはこの手順に慣れている。**毎回この形で、説明し直さずに出す。** 別の方式を考え出さない。

## 手順（固定）

1. 私がコマンドを**1行のコードブロック**で出す
2. 中森さんがそのコマンドをコピーしてターミナルで実行 → 入力待ちになる
3. **その後で**、中森さんがサービスの画面で値をコピーする
4. ターミナルに貼って Enter →「保存しました（〇文字）」と出る

**順番を逆にしない。** 「値をコピー → コマンドをコピー」と案内すると、クリップボードの値が上書きされて消える（2026-10-16 Meta、2026-10-18 Cloudflare で指摘された）。

## どのコマンドを出すか

### .env に入れるとき

```bash
~/.claude/scripts/set-secret.sh <.envのパス> <キー名>
```

- 既存の同じキーは置き換え、他の行はそのまま残す。値は画面に出ず、文字数だけ表示される
- 秘密ではない値（ID など）は、私が直接 .env に書いておく

### ~/.config/ に単体のファイルで置くとき（API トークンなど）

```bash
echo "<サービス名> のトークンを貼り付けて Enter（画面には表示されません）:"; read -s T && printf '%s' "$T" > ~/.config/<ファイル名> && chmod 600 ~/.config/<ファイル名> && unset T && echo "保存しました"
```

- ファイル名は `<サービス>_<用途>`（例 `cloudflare_token_bingoya`、`supabase_token`）

## 保存の後に私がすること

- 中身は表示しない。文字数だけ確かめる（`wc -c`）。貼り付けが重複していないかもここで見る（2026-10-10 に `read -s` で値が3回分入った例あり）
- API の疎通を1回確かめる（例 Cloudflare は `/user/tokens/verify`）
- トークン本体をチャット・commit message・ログに出さない

## やらないこと

- チャットに値を貼らせる
- エディタで .env やファイルを開いて手で貼らせる
- Terminal パネルに私がタブを開いて待たせる（中森さんのいつものやり方ではない）
- pbpaste でクリップボードから読む方式を勝手に選ぶ
